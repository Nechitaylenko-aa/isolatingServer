# fcpp-agent: Правила кодинга и системные инварианты

## 1. Стилистика кода (C++20)

### Оформление фигурных скобок:
* Все открывающие `{` и закрывающие `}` фигурные скобки ОБЯЗАНЫ находиться на **новых отдельных строках** (для классов, структур, методов, пространств имен, `if`, `else`, `switch`, `for`, `while` — везде без исключений).

### Именование типов и сущностей (Naming Conventions):
* **Интерфейсы:** префикс `I` + CamelCase (например, `IIndexParser`).
* **Классы:** префикс `C` + CamelCase (например, `CSQLiteIndex`).
* **Структуры:** префикс `S` + CamelCase (например, `SSymbolLocation`).
* **Перечисления (Enum):** 
  - Глобальные перечисления: префикс `S` + CamelCase, строго **ЗАПРЕЩЕНО** использовать `enum class`, использовать только классический `enum`.
  - Перечисления внутри пространств имен/классов: префикс `E` + CamelCase.
* **Члены классов:** строго префикс `m_` + snake_case (например, `m_db_path`).
* **Методы классов и структур:** строго в `snake_case` (например, `get_symbol_by_usr`).

### Структурирование и документация:
* **Разделение:** Любой класс и структура с методами ОБЯЗАНЫ разбиваться на заголовочный файл (`.h`) и файл реализации (`.cpp`). Никакого исполняемого кода в хидерах.
* **Документация:** Каждый класс, структура и метод в заголовочном файле (`.h`) ОБЯЗАНЫ иметь подробное Doxygen-описание (`/** ... */`).

---

## 2. Архитектурные догмы (Системные правила)

* **Закрытая безопасность:** Все, что явно не разрешено — жестко запрещено. Никаких допущений.
* **Детерминизм мест:** Агент ничего не ищет. Если сущности нет в конфиге/стандартном месте — `FAIL`.
* **Zero-Window:** Файлы целиком в LLM не передавать (только срезы).


## 3. Оптимизация работы со строками (Enum-массивы вместо Switch-case)

### Базовый принцип:
* **Запрет на сырые строки:** Внутренняя логика, типы сущностей, статусы и команды ОБЯЗАНЫ оперировать строго перечислениями (`enum` / `enum class`), а не текстовыми строками.
* **Запрет на `switch-case` для строкового маппинга:** Вместо функций преобразования вида `switch(value) { case EType::A: return "A"; }` ОБЯЗАТЕЛЬНО использовать статические массивы строк с прямой индексацией по enum.

### Критерии органичного применения (Применять «с умом»):
Этот подход применяется для **стабильных, фиксированных системных словарей**, размер которых известен на этапе компиляции, и где важна максимальная скорость доступа (сложность \(O(1)\)) и экономия токенов/контекста:
1. Имена CLI-команд и флагов.
2. Типы C++ сущностей для индекса (Class, Method, Struct и т.д.).
3. Состояния генераций (`BUILDING`, `ACTIVE`, `FAILED`).
4. Типы типизированных ошибок приложения (`ErrorKind`).

### Пример реализации для локальных/закрытых контекстов (Enum Class):
```cpp
enum class EProjectState
{
    Active,
    Suspended,
    Failed,
    Count // Маркер количества для инициализации массива
};

// Размещается в файле реализации (.cpp), чтобы не засорять хидер глобальными строками
static const char* const m_state_names[static_cast<size_t>(EProjectState::Count)]
{
    "Active",
    "Suspended",
    "Failed"
};
```

### Исключения (Где этот подход НЕ применяется):
* Динамические данные, приходящие из LLM или файлов проекта (где состав строк заранее неизвестен).
* Глобальные открытые перечисления (согласно разделу 1, там используется классический `enum` без `Count`, и маппинг может ложиться на ассоциативные контейнеры, если это оправдано архитектурой).
