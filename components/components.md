# Цикл опроса сервера

>Полная картина, компонент за компонентом, в порядке стадий.

## Стадия 1 — зависят только от tor/project_type/состава тела

### Фильтр осветлительный

Запрос: Q, давление на входе, температура, целевая скорость фильтрации (норматив).
Ответ → телу: диаметр, высота слоя, v_max, enum загрузки, крупность загрузки; отдельно Qном/Pном (паспортные, не путать с тем, что просили) — не идут в тело, идут в отчёт/снимок тени.
Ответ → другим: диаметр → трубе на выходе; v_max → насосу перед собой (уже реализовано, max_allowed_pressure_pa()); крупность загрузки → интенсивность промывки → ёмкости (уже реализовано, backwash_volume_required()).
> Новое: тень дополнительно отслеживает нерастворённое железо (EMU_CONCENTRATION + EChemicalElement::Fe_undissolved) — та же формула эффективности, что мутность/цветность, без нового вывода/добавления параметра (просто ещё один вход-выход по той же логике).

> При превышении лимита по мутности ИЛИ цветности → SReagentRequirement (коагулянт, доза — //TODO(нет данных)) в CInfoBus, отдельно от SEquipmentRequest на само оборудование — уже реализовано.

### Фильтр ионного обмена

Ответ → телу: жёсткость на выходе (эффективность — //TODO(нет данных), сейчас константа 0.9).
Ответ → другим: диаметр → трубе/насосу; объём загрузки ионита → ёмкости (regeneration_rinse_volume_required(), уже реализовано); Qном/Pном — не читаются отдельно, //TODO(нет данных).

### Фильтр сорбционный

Запрос: Q, давление, температура.
Ответ → телу: запах/привкус на выходе — эффективность //TODO(нет данных) (константа 0.6), состав самого ответа от каталога тоже //TODO(нет данных) — сейчас не читаем вообще ни одного поля, кроме факта подбора.
Ответ → другим: пока ничего — реагентной подготовки перед собой не запрашивает (решили раньше — предположение, тоже //TODO, если для сильного запаха реально нужен доокислитель).

### Аэратор

Запрос: Q, концентрация Fe (Fe_dissolved), концентрация Mn (аналогичный подход), возможно H₂S — лимиты по ним реально есть в таблице требований (не гадаю пороги, они у тебя в water_drink_requirements).
Ответ → телу: обнулить Fe_dissolved → 0; добавить новый CBodyParam с Fe_undissolved = перенесённое значение (масса сохраняется, форма меняется — упрощение, которое ты подтвердил).
Ответ → другим: пока ничего вниз по потоку явно не идёт (не проверяли, нужен ли расход воздуха как отдельный конверт станции, аналогично реагенту) — оставляю как открытый пункт, не решаю сам.

### Обратный осмос

Запрос: Q, минерализация/сухой остаток, давление на входе.
Ответ → телу: состав пермеата (по сути "почти всё убрано" — какой конкретно параметр обнулять/пересчитывать явно не решали, //TODO).

### Ёмкость

Запрос: Q, сумма объёма промывки/отмывки от фильтров выше по потоку (уже реализовано, sum_upstream_backwash_demand()).
Ответ → телу: не изменяет тело содержательно (put_ob — тождественное преобразование, как и раньше).
Ответ → другим: высота → насосу перед собой (min_required_pressure_pa(), уже реализовано, но сейчас только для параллелепипеда — баг, нашли на этом же заходе); нужно расширить: enum формы (цилиндр/параллелепипед/куб), Vном, H, и по форме — либо диаметр, либо (X, Z).
Стадия 2 — труба (зависит от 1/1.5)

### Труба

Запрос: локальные Q/P от конкретного соседа (фильтра/ёмкости, тем же кастом, что у насоса) + тип проекта (get_owner()->get_project_type(), уже реализовано верно).
Ответ → телу: труба тело не трогает вообще (не в потоке).
Ответ → другим: диаметр → клапанам/воздуходувке/узлу учёта; материал — сейчас заглушка через equip_name, отдельного поля нет.
Известный баг (не новые данные, а недоделанный код): сейчас берёт общий tor->hourInputMax() вместо локального соседа — нужно исправить на тот же каст-подход, что у насоса.
Стадия 3 — всё остальное

### Насосная станция

Запрос: Q, минимальный напор (от ёмкостей ниже, максимум), предельное давление (от фильтров ниже, минимум) — уже реализовано.
Ответ → телу: давление на выходе (пишется в m_nominal_pressure, уже реализовано).
Ответ → другим: то же давление — фильтрам/ёмкостям ниже по потоку (уже используется ими через body->get_si_pressure()).
Известный пробел: Qном (паспортный расход насоса) не читается отдельно — стоит добавить.

### Отсечной клапан

Запрос: DN (от трубы), рабочее давление (от соседа), тип среды, класс герметичности A (детерминировано, питьевая вода).
Ответ → телу: не трогает (идентичный проход, как задвижка).
Ответ → другим: ничего вниз по потоку не нужно — терминальный узел в этом смысле.

### Трёхходовой клапан

Запрос: Q насоса, ΔP допустимые потери (дефолт 0.2 бар — //TODO, взят из твоего же примера), рабочее давление насоса, режим (дефолт "промежуточные положения", консервативно).
Ответ → телу: не трогает.
Ответ → другим: ничего.
Топология: 1 вход, 2 выхода (тот же приём, что у осмоса), но активен один за раз — переключение, не разделение.

Воздуходувка

Запрос: площадь фильтра (из тени фильтра), интенсивность продувки (дефолт 55 л/(с·м²)), КПД (дефолт 0.7).
Ответ → телу: не трогает (воздух не в водном теле).
Ответ → другим: ничего дальше не нужно.
