### R1 — ReAct теряет фактический уровень модели при возврате ответа
- **Приоритет:** P1 — качество и достоверность диагностики.
- **Тип:** подтверждённый архитектурный дефект.
- **Наблюдение:** `CReActAgent::run` сам выбирает и меняет уровень в `levels/level_index`, но наружу возвращает только `bool` и текст. В `CAskService::ask` после успеха уровень кандидата безусловно принимается как `quality_levels.back()`. Поэтому лог оценки может приписать ответ Remote даже если его сгенерировал Lite/Main; проверка также рассматривает Remote как уровень кандидата и обычно рецензирует ответ той же моделью, а не следующим независимым уровнем.
- **Исправление:** вернуть фактический уровень (или метаданные результата) из ReAct; передать его в quality gate. Если доступен следующий независимый уровень — использовать его; если нет — явно маркировать self-review и применять осознанную политику.
- **Проверка:** тест маршрута с фальшивыми моделями, где ReAct завершает работу на Lite/Main/Remote; проверить кандидатский уровень, ревьюера и решение об эскалации.
- **Статус:** DONE — в `4fa5337` добавлен фактический уровень выхода ReAct и fail-closed проверка неизвестного уровня. Интеграционные тесты проверяют review gate; CI `38131774012` для `8285e69` зелёный (94/94 теста).

### R7 — Протокол молча игнорирует некоторые неверные типы параметров
- **Приоритет:** P3.
- **Тип:** потенциальная проблема API-контракта.
- **Наблюдение:** `CProtocolServer::parse_request` читает поля только если тип совпал, но часто возвращает успех, игнорируя переданный параметр неправильного типа; `params` отсутствующего или не-объектного типа тоже трактуется как пустой объект для любого метода. Это может превращать опечатку плагина в непонятную ошибку позднего этапа.
- **Исправление:** сопоставить поведение с `plugin_api.md`; определить, какие поля обязательны и где нужен строгий type error, не ломая сознательную обратную совместимость.
